# 🚀 سير عمل التطوير التتابعي للطلبات (Sequential Requests Workflow)

> **الحالة:** شرط إلزامي صارم (NON-NEGOTIABLE)  
> **النطاق:** يُطبق على كل مشروع وأي سكريبت أتمتة جديد يتم بناؤه في بيئة العمل.

---

## 🏗️ المبادئ الستة الأساسية (The 6 Golden Rules)

### 1️⃣ التحقق خطوة بخطوة (Request-by-Request Flow)
* **القاعدة:** يتم بناء وتجربة طلبات الـ API **ريكويست ريكويست بالترتيب**.
* **الآلية:** كلما تم إنجاز طلب، يتم مقارنة ترويساته (Headers)، والـ Payload الخاص به، والـ Response المرتجع بالملي مع السجل الأصلي في ملف الـ HAR لضمان المطابقة والدقة بنسبة 100%.

### 2️⃣ نظام التسلسل الرقمي للإصدارات (Strict Versioning Pattern)
يأخذ كل سكريبت أو ملف أتمتة اسمًا رمزيًا صارمًا يعكس ترتيب التطوير والإصدار:
* **تنسيق الاسم الأساسي:** `[Step]_[Tech/StepName]_[Target/Site/App].py` (مثال: `01_sign_up_fxpro.py`).
* **التعديل/التصحيح:** في حال تعديل أو تصحيح نفس الخطوة -> **نضيف الإصدار العشري بجانب الخطوة** مع الحفاظ على نفس الاسم لسهولة التراجع (مثال: `01.02_sign_up_fxpro.py`).
* **الخطوة التالية:** عند الانتقال لطلب جديد أو مرحلة جديدة -> **نزود رقم الخطوة ونبدأ بدون إصدار عشري** (مثال: `02_submit_answers_fxpro.py`).
* **الشغل الحر (Sandbox):** لو بنعمل ريفاكتور كلي، إضافات جانبية، أو تجارب حرة خارج السياق التتابعي -> **ننشئ خطوة ساندبوكس مستقلة** (مثال: `03_sandbox_fxpro.py` أو `03.02_sandbox_fxpro.py`).

### 3️⃣ مجلد الروت المحلي المزدوج (Double Local Root)
* **القاعدة:** كل مشروع فرعي نشط (مثل `F_Fx_Pro_SMS`) يجب أن يمتلك مجلد `Root` محلي متكامل خاص به (`F_Fx_Pro_SMS/Root/`).
* **المحتويات:** يحتوي على ملفات التزامن الأربعة الأساسية:
  1. `ai_state.json`: لتسجيل الحالة اللحظية للخطوة الحالية بدقة والـ Tag النشط.
  2. `TASK.md`: لتتتبع التقدم بالـ Checkboxes لكل ريكويست.
  3. `memory.md`: لتسجيل أي اكتشاف تقني جديد أو تخطي حماية بالدليل والسطر.
  4. `keys.txt`: لحفظ الكوكيز والتوكنات والمفاتيح المستخرجة حياً.

### 4️⃣ الـ Git Commit الإلزامي الفوري
* **القاعدة:** يُمنع منعًا باتًا الانتقال من خطوة إلى أخرى أو البدء في ريكويست جديد قبل إجراء **Git Commit فوري** يؤمن حالة النجاح الحالية ويحميها من الضياع.
* **الرسالة:** يجب أن تكون رسالة الكوميت تفصيلية وتوضح رقم الخطوة والإصدار (مثال: `git commit -m "🚀 [FxPro 01] Successfully completed Sign-Up API request"`).

### 5️⃣ البانرات النيونية الملونة للبداية والنجاح (Neon CLI Banners)
يجب أن يطبع كل سكريبت يتم تشغيله واجهات بصرية ملونة ومبهجة في التيرمينال تعبر عن الحالة:
* **بانر البداية (Start Banner):** يوضح بوضوح بالألوان النيونية: "جاري البدء في تنفيذ خطوة كذا وكذا..." مع تدوين الـ Commit.
* **بانر النجاح (Success Banner):** عند اكتمال الخطوة بنجاح، يُطبع بانر نيون مبهج وضخم يقول: "تم النجاح في كذا وكذا وكذا بنسبة 100%!" مع تأكيد الحفظ والـ Git Commit النهائي.

### 6️⃣ الدمج والالتزام في ملف الأجنتس الرئيسي (AGENTS.md)
* يتم دمج هذه القواعد في قلب ملف الإرشادات الرئيسي `.agents/AGENTS.md` لضمان قراءتها والتزام الأجنت بها فورياً وتلقائياً في كل مرة يبدأ فيها العمل.
