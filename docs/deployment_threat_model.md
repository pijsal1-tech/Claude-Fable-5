## 1. العقد الحاكم: أداة تطوير محلية أحادية المستخدم

هذا هو **الافتراض التأسيسي** الذي بُني عليه كل قرار أمني في المشروع
(عقد RRR §5 — localhost أحادي المستخدم):

| البند | القيمة الافتراضية | الدليل |
|---|---|---|
| عنوان الربط | `127.0.0.1` (افتراضي `--host`) | server.py:1863 @ 7d39e9f |
| المنفذ | `5000` (افتراضي `--port`) | server.py:1861 @ 7d39e9f |
| المصادقة | **لا توجد** — لا login ولا توكنات ولا Authorization header في أي مسار | مسح `grep -in 'auth\|login'` على server.py + routes/*.py @ 7d39e9f = صفر نتائج |
| تعدد المستخدمين | غير مدعوم — حالة جلسة واحدة لكل اتصال WS، وموارد مشتركة (cmd_runner.cwd مثلًا) عملية-واحدة | server.py:950 (`_build_session_context`) + routes/run.py:41 @ 7d39e9f |
| TLS | لا يوجد — `app.run` مباشر (Flask dev server) | server.py:2137 @ 7d39e9f |

**النتيجة**: حد الثقة = حدود الجهاز المحلي. كل من يستطيع الوصول إلى
`127.0.0.1:5000` على هذا الجهاز يملك **كامل صلاحيات الأداة** — وهي
بالتصميم صلاحيات واسعة (قراءة/كتابة ملفات المشروع + تنفيذ أوامر
بموافقة). هذا مقبول لأن المستخدم الوحيد هو مالك الجهاز نفسه.

## 2. الأصول المحمية (ماذا نحمي؟)

1. **نظام الملفات خارج جذر المشروع** — يجب ألا تصل إليه أي عملية
   قراءة/كتابة صادرة عن الـ agent أو الواجهة.
2. **الملفات السرية داخل المشروع** (.env، مفاتيح، شهادات) — يجب ألا
   تُقرأ أو تُسرّب إلى سياق النموذج.
3. **تنفيذ الأوامر** — يجب ألا يُنفَّذ أمر إلا بقرار بشري (وضمن allowlist
   للـ agent).
4. **سلامة المشروع عند الاستعادة** — أرشيف ZIP خبيث يجب ألا يكتب خارج
   الجذر.

## 3. الضوابط القائمة (خريطة الدفاعات)

### 3.1 احتواء المسارات (Path Containment)

- `chain/path_policy.py:resolve_workspace_path` (:54 @ 7d39e9f) —
  التطبيع والاحتواء تحت جذر العمل؛ الدلالة المرجعية للاحتواء في
  المشروع كله.
- أدوات الـ agent كلها تمر عبره + فلتر `is_secret_file`

### 3.2 حجب الأسرار (Secrets Denylist)

- `chain/path_policy.py:is_secret_file` (:28–52 @ 7d39e9f): يحجب
  `.env` وكل `.env.*` (عدا `.env.example`)، وأسماء/امتدادات denylist،
  ومجلدات `.ssh`/`.aws`/`.git`/`.gcloud`/`.kube`.
- config.yaml لا يحوي مفاتيح API فعلية — الحقول تعليقات معطلة
  (config.yaml:215/220 @ 7d39e9f)؛ قاعدة V3 §0: لا credentials في
  ملفات المستودع أبدًا.

### 3.3 بوابة تنفيذ الأوامر (طبقتان مستقلتان)

**الطبقة 1 — Allowlist (R-504، fail-closed منذ TSK-617/قرار D-1):**
- `CommandPolicy` @ chain/agent_tools.py:60 — القائمة ملكية المشروع
  (config.yaml `agent.command_allowlist`) لا الـ agent؛ المطابقة حرفية
  بعد توحيد الفراغات — **لا مطابقة بادئة** (chain/agent_tools.py:80–93).
- غياب/فساد القسم ⇒ `enforce=True` بقائمة فارغة = **رفض كل الأوامر**
  (chain/agent_tools.py:96–112 @ 7d39e9f) — لا وضع legacy صامت.

**الطبقة 2 — موافقة بشرية (ApprovalGate / T-013):**
- `APPROVAL_TOOLS = {"run_command"}` (chain/agent_tools.py:40) — أمر
  مسموح في الـ allowlist **لا يزال** يحتاج موافقة المستخدم عبر بطاقة
  الطرفية (تدفق `agent_step`/`awaiting_approval` —
  docs/ws_frame_protocol.md §4.4).
- راية `force_command_approval` (config.yaml:28، القراءة
  server.py:178–195 @ 7d39e9f): مفعّلة ⇒ حتى مسار REST `/api/run`
  يمر ببوابة الموافقة إلزاميًا (routes/run.py:57–59، TSK-502/NF-16).
  - **تنبيه توثيقي**: القيمة الحالية في المستودع `false`
    (config.yaml:28)؛ الافتراض عند غياب المفتاح `True`
    (server.py:195) — أي أن الحذف أكثر أمانًا من الضبط على false.

### 3.4 تحصين استعادة ZIP (TSK-105/NF-15 — Zip-Slip guard)

## 4. نموذج التهديد

### 4.1 داخل حد الثقة (localhost) — مقبول بالتصميم

| التهديد | الوضع | التبرير |
|---|---|---|
| عملية محلية أخرى بنفس صلاحيات المستخدم تتصل بـ :5000 | **خارج النموذج** | من يملك تشغيل عمليات محلية يملك أصلًا كل ما تملكه الأداة (ملفات المستخدم وتنفيذ الأوامر) — الأداة لا تضيف صلاحية جديدة |
| CSRF من صفحة ويب خارجية نحو `http://127.0.0.1:5000` | **مخفَّف جزئيًا بالبنية، غير معالج صراحة** | لا حماية CSRF مبنية؛ المسارات الخطرة POST/JSON (routes/run.py:25 `request.get_json`) — النماذج البسيطة cross-origin لا ترسل JSON، وWS من أصل خارجي غير محجوب. **أي تصلب إضافي = قرار منتج** (انظر §5) |

### 4.2 التهديدات المعالَجة داخل النموذج

| التهديد | الضابط | المرساة |
|---|---|---|
| هروب الـ agent من جذر المشروع (path traversal) | resolve_workspace_path + الاحتواء بعد التطبيع | §3.1 |
| تسريب أسرار المشروع لسياق النموذج | is_secret_file denylist | §3.2 |
| النموذج يبتكر أوامر تنفيذ حرة | CommandPolicy fail-closed + مطابقة حرفية | §3.3 ط1 |
| تنفيذ أمر دون علم المستخدم | ApprovalGate إلزامي لـ run_command | §3.3 ط2 |
| أرشيف استعادة خبيث يكتب خارج الجذر | Zip-Slip guard رفض-كامل | §3.4 |
| XSS عبر محتوى يعرضه النموذج | escapeHtml (+ DOMPurify قادمة TSK-703) | §3.5 |

### 4.3 خارج النموذج صراحةً (قرارات واعية موثقة)

- **مهاجم شبكي**: لا يوجد — الربط 127.0.0.1 لا يستمع على الشبكة.
- **مستأجر ثانٍ على نفس الأداة**: غير مدعوم — لا عزل جلسات تنافسية.
- **نموذج LLM خبيث بالكامل**: الدفاع = بوابة الموافقة البشرية
  والـ allowlist؛ لا sandbox لتنفيذ الأوامر الموافَق عليها (الأمر
  الموافَق عليه يعمل بصلاحيات المستخدم كاملة).
- **Flask dev server**: `app.run` (server.py:2137) ليس خادم إنتاج —
  مقبول حصرًا ضمن عقد localhost.

## 5. أي تعريض أبعد من localhost = قرار واعٍ موثَّق

**القاعدة**: تشغيل الأداة بـ `--host 0.0.0.0` (أو أي عنوان غير loopback)
**يكسر العقد التأسيسي** وينقل كل بنود §4.1 و§4.3 فورًا إلى داخل نموذج
التهديد **بلا أي ضابط قائم يغطيها**. تحديدًا، من يفعل ذلك يعرّض:

1. **تنفيذ أوامر عن بُعد**: `/api/run` (routes/run.py:22) بلا مصادقة —
   مع `force_command_approval: false` الحالية يكون تنفيذًا مباشرًا
   (need_approval=False @ routes/run.py:58).
2. **قراءة/كتابة/حذف ملفات عن بُعد**: `/api/file/<path>` GET/POST/DELETE
   (routes/files.py:67/103/115) بلا مصادقة.
3. **استعادة نسخ / تبديل مشروع عن بُعد**: routes/backups.py:38،
   routes/project.py:25.
4. **كامل قناة WS**: `/ws` (server.py:1716) — كل الأنواع الـ 25 في
   docs/ws_frame_protocol.md §3 متاحة لأي متصل.

**الحد الأدنى غير القابل للتفاوض قبل أي تعريض** (وكلها **غير موجودة
اليوم** — تتطلب مهام هندسية مستقلة بقرار مالك):
مصادقة على كل HTTP+WS، وTLS، وCSRF/Origin checks، وخادم WSGI إنتاجي
بدل dev server، وضبط `force_command_approval: true`، ومراجعة
allowlist الأوامر، وعزل تنفيذ الأوامر (sandbox).

> هذه الوثيقة **لا ترخّص** أي تعريض — هي تجعل كلفته مرئية فقط.
> القرار وتنفيذ متطلباته ملكية المالك حصريًا.

## 6. قائمة فحص التشغيل الآمن (الوضع القائم)

- [ ] شغّل دائمًا بالافتراضيات: بلا `--host`، بلا `--debug`.
- [ ] لا تضع مفاتيح API في config.yaml أو أي ملف مُتتبَّع (V3 §0) —
      استخدم آلية المزود خارج المستودع.
- [ ] أبقِ `agent.command_allowlist` أضيق ما يمكن (قائمة أقصر أأمن —
      chain/agent_tools.py:96 docstring).
- [ ] فضّل حذف مفتاح `force_command_approval` نهائيًا (غيابه = True
      الافتراضي الأكثر أمانًا) أو اضبطه `true` صراحة.
- [ ] لا تستعد نسخة ZIP من مصدر لا تثق به — الحارس يمنع الكتابة خارج
      الجذر لكنه لا يفحص محتوى الملفات المستعادة داخل الجذر.
