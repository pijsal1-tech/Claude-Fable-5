# دليل تشغيل عدة قياس الأداء — CEV-F-006 على جهاز حقيقي

> **TSK-738b (القرار 11 / D-21)** — «هذا اختبار أداء فقط، وليس تطويرًا».
> السؤال المطلوب حسمه: الرجفة الملحوظة في بيئة الاختبار (Sandbox بـ2 vCPU)
> — هل هي **بيئية** (مزاحمة CPU) أم **مشكلة أداء حقيقية** في الكود؟

---

## 1. خطوات التشغيل

### المتطلبات
- Python 3.10+ وتبعيات المشروع مثبَّتة (`pip install -r requirements.txt`).
- لا يحتاج السكربت أي خادم ولا اتصال شبكي — قراءة فقط + مجلد مؤقت يُحذف.

### Linux / macOS
```bash
cd <مجلد-المشروع>
python scripts/perf_probe.py --json
```

### Windows
```powershell
cd <مجلد-المشروع>
python scripts\perf_probe.py --json
```

يطبع تقريرًا نصيًا + سطر JSON للمقارنة الآلية. رمز الخروج:
`0` = كل القياسات دون العتبة، `1` = قياس تجاوزها.

> نصيحة للقياس النظيف: أغلق البرامج الثقيلة (متصفح بعشرات التبويبات،
> مضاد فيروسات يفحص لحظيًا) وشغّل مرتين وخذ الثانية (تسخين كاش القرص).

---

## 2. خط الأساس المرجعي (Sandbox — نفس بيئة اختبارات CEV)

قياس مُرسَّخ بتاريخ 2026-08-05 على HEAD ما بعد إغلاق D-19 «2→…→9»:

| القياس | Sandbox (2 vCPU / 985MB RAM / Python 3.13) | العتبة |
|---|---|---|
| زمن استيراد server.py (بديل «فتح المحرر») | **0.89s** | — (استرشادي) |
| api_search على 5k ملف (أفضل-من-3) | **0.160s** | < 1.0s ✅ |
| tool_search_code على 5k ملف (أفضل-من-3) | **0.134s** | < 1.0s ✅ |
| ذروة RSS لعملية القياس | **41MB** | — (استرشادي) |

JSON الخام:
```json
{"import_server_s": 0.888, "api_search_s": 0.1598, "tool_search_s": 0.1336,
 "threshold_s": 1.0, "verdict_ok": true, "cpu_count": 2,
 "mem_total_mb": 985, "python": "3.13.13"}
```

> سياق CEV-F-006: تحت **حمل الحزمة الكاملة** (كل الاختبارات متزامنة على
> 2 vCPU) كان قياس البحث يتجاوز 1s أحيانًا رغم أن زمنه المعزول ~0.13s —
> وهذا عين ما دفع لتقسية أفضل-من-3 (TSK-CEV-119). القياس المعزول أعلاه
> يؤكد أن قدرة الكود الحقيقية أدنى من العتبة بـ~7×.

## 3. تفسير النتائج (عقد الحكم)

| النتيجة على جهازك | الحكم | الإجراء |
|---|---|---|
| كل القياسات دون العتبة (وأسرع من خط الأساس غالبًا) | الرجفة السابقة **بيئية** — Sandbox محدود الموارد | يُغلق CEV-F-006 نهائيًا بلا تعديل كود |
| قياس بحث ≥ 1.0s | مؤشر **مشكلة أداء حقيقية** | أرسل التقرير كاملًا (النص + JSON) ليُفتح TSK إصلاح |
| استيراد server.py أبطأ بكثير من 0.89s (مثلًا > 5s) | استرشادي — قد يكون قرصًا بطيئًا أو مضاد فيروسات | أعد التشغيل مرة ثانية (كاش دافئ) قبل الحكم |

## 4. القياسات اليدوية المكمِّلة (سلاسة الواجهة وFPS)

واجهة المحرر HTML/JS تعمل في متصفحك — هذه القياسات لا تُجرى آليًا
(نفس مبدأ P-11: لا ادعاء قياس آلي لما يتطلب بيئة لا نملكها):

1. **زمن الفتح المحسوس**: شغّل `python server.py` وافتح
   `http://127.0.0.1:5000` — قس من الضغط حتى ظهور الواجهة كاملة
   (DevTools ▸ Network ▸ خانة Load).
2. **FPS والسلاسة**: DevTools ▸ ⋮ ▸ More tools ▸ **Rendering** ▸ فعّل
   *Frame Rendering Stats* — يظهر عداد FPS حي. مرّر في محادثة طويلة
   وافتح/أغلق الألواح: انخفاض مستمر تحت ~30 FPS = رجفة حقيقية.
3. **سرعة الاستجابة**: DevTools ▸ **Performance** ▸ سجّل 10 ثوانٍ من
   الاستخدام العادي — ابحث عن مهام طويلة (Long Tasks > 50ms) متكررة.
4. **CPU/RAM أثناء الاستخدام**: مدير المهام (Windows) أو `htop` —
   راقب عملية python وعملية المتصفح أثناء بث رد طويل.

سجّل الملاحظات وأرسلها مع مخرَج `--json` — تُلحق النتيجة بسجل
القرار 11 وتحسم مصير CEV-F-006.
