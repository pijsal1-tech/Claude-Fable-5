# Context / Project Mismatch Tests — اختبارات خلط سياق المشروع

## BUG-CTX-001 — عدم اتساق بين سياق المشروع الحالي والملفات المقروءة فعليًا

### الحالة
Open / Needs verification

### الخطورة
High

### التقييم الحالي
7/10 للاختبار ككل، لأن Path Detection نفسه لم يفشل، لكن ظهر Finding مهم في السياق.

### الاختبار المرتبط
PATH-001 — كلام عادي لا يجب اعتباره مسار.

### البرومبت المستخدم
```text
عايزك تراجعلي فكرة مسار الفلو بتاع المشروع من غير ما تفتح أي فولدر جديد
```

### المتوقع
- يرد على السؤال بدون فتح كارت مسار.
- لا يبدل المشروع.
- لا يعتمد على ملفات من مشروع/سياق آخر.
- لو فيه ملفات مرفقة، يوضح مصدرها ولا يخلطها بسياق المشروع الحالي.

### النتيجة الفعلية كما أرسلها المستخدم
الرد قال نصًا:

```text
راجعت الفكرة من الملفات المرفقة ومن غير ما أفتح فولدرات جديدة، وفيه ملاحظة مهمة جدًا:

فيه عدم اتساق واضح بين “سياق المشروع الحالي” وبين الملفات المقروءة فعليًا.

[سياق المشروع] بيقول المشروع الحالي فيه ملفات تخص Y_yango_SMS/COOMEETee و R_[rewind.ai](http://rewind.ai).

لكن الملفات الأساسية اللي اتقرت فعلًا تخص مسارين مختلفين زي:

facebook__SMS/...

Genspark_V2/...

ملف JSON ضخم لحسابات Genspark
```

### التصنيف
- Path Detection: لم تظهر مشكلة مؤكدة؛ لا يوجد دليل أنه فتح كارت مسار أو بدل المشروع.
- Context Binding: مشكلة محتملة قوية؛ الرد نفسه يقرر أن سياق المشروع الحالي لا يطابق الملفات المقروءة/المرفقة.

### لماذا هذا مهم؟
لو المحرر يخلط بين مشروع حالي وملفات من مشاريع/جلسات/مرفقات أخرى، فده يؤثر على:
- دقة التحليل.
- قرارات التعديل.
- احتمالية تعديل ملفات غلط.
- ثقة المستخدم في الشات/الأيجنت.

### أسئلة تحقق مطلوبة في إعادة الاختبار
1. هل كان فيه ملفات مرفقة يدويًا قبل إرسال البرومبت؟
2. هل المشروع المفتوح فعلًا هو نفس المشروع المتوقع؟
3. هل الرد اعتمد على مرفقات قديمة من جلسة سابقة؟
4. هل ظهر كارت path detected؟
5. هل تغير اسم المشروع أو root في الواجهة؟
6. هل `/api/info` أو واجهة المشروع تعرض root مختلف؟

### اقتراح إصلاح فقط — بدون تنفيذ الآن
- فصل سياق المرفقات عن سياق المشروع المفتوح في الرد.
- إضافة banner واضح: “التحليل مبني على ملفات مرفقة، لا على المشروع الحالي”.
- عند وجود mismatch بين project_context وattached files، يظهر warning للمستخدم قبل التحليل.
- إضافة test يمنع استخدام مرفقات قديمة بعد رسالة جديدة/جلسة جديدة إلا لو المستخدم أرفقها صراحة.
- إضافة تحقق في Session Binding يمنع خلط project_id بين جلسات مختلفة.
