# Attachment Context Tests — اختبارات المرفقات والسياق القديم


## BUG-ATT-001 — attached-content خارجي يظهر رغم طلب عدم استخدام مرفقات أو سياق قديم

### الحالة
Open / Confirmed twice

### الخطورة
High

### البرومبت
```text
راجع المشروع المفتوح الحالي فقط. لا تستخدم أي مرفقات، لا تستخدم سياق قديم، ولا تستخدم أي ملفات من خارج المشروع المفتوح. اذكر أول 5 ملفات اعتمدت عليها، ولو مش قادر تحددها بوضوح قول UNKNOWN بدل التخمين.
```

### المتوقع
- لا يتم تمرير أي `<attached-content>` إلى النموذج.
- الرد لا يحتاج يذكر أنه استبعد README خارجي؛ لأن هذا المحتوى لا يجب أن يصله أصلًا.
- في شات جديد، لا توجد مرفقات قديمة إلا لو المستخدم أرفقها صراحة.

### الفعلي
في محاولتين، الرد أشار إلى وجود attached content خارجي:
```text
<attached-content source="file:README.md">
Y_yango_SMS/COOMEETee
D:/SMS/.hRhRhRhRhRhR/...
```

### التصنيف
Bug في إدارة attached context/session context. النموذج أحسن التصرف واستبعده، لكن طبقة السياق ما زالت تمرر مرفقات/سياق خارج النطاق.

### الخطورة العملية
- ممكن في طلب آخر النموذج يعتمد على README الخارجي بدل استبعاده.
- ممكن يخلط مشاريع.
- ممكن يسرّب أو يحلل ملفات خارج نطاق المستخدم.
- الاختبار لا يجب يعتمد على "حسن تصرف" النموذج؛ المنع لازم يحصل قبل prompt.

### اقتراح إصلاح فقط — بدون تنفيذ الآن
- Clear attachments عند إنشاء شات جديد أو جلسة جديدة.
- دعم أمر صريح في prompt أو UI: ignore attachments => لا تمرر attached_context.
- إظهار badge بعدد المرفقات الحالية ومصدرها.
- إضافة اختبار regression: بعد New Session، لا يظهر `<attached-content>` من جلسة سابقة.

### Reproductions

#### Reproduction 1
- التاريخ: 2026-08-06
- النتيجة: الرد قال إن `<attached-content source="file:README.md">` يشير إلى `Y_yango_SMS/COOMEETee` وتم استبعاده.

#### Reproduction 2
- التاريخ: 2026-08-06
- شات جديد.
- النتيجة: الرد كرر وجود README خارجي بمسار `D:/SMS/.hRhRhRhRhRhR/...` وتم استبعاده.


## ATT-002 — شات جديد مرتين: النظام ما زال يرى project_root و README.md كمصادر مرفقة/سياق

### الحالة
FAIL / Confirmed twice

### الخطورة
High

### البرومبت
```text
هل يوجد أي attached-content أو ملفات مرفقة أو سياق خارجي داخل رسالتي الحالية؟ أجب بنعم أو لا فقط، ثم اذكر أسماء أي مصادر مرفقة ظاهرة لك. لا تحلل المشروع.
```

### المتوقع
- إذا لم يرفق المستخدم ملفات يدويًا، يجب أن تكون الإجابة: لا، أو توضيح أن `project_root` سياق نظامي تلقائي وليس مرفقًا يدويًا.
- لا يتم تشغيل تحليل شجرة المشروع لأن المستخدم قال صراحة: `لا تحلل المشروع`.
- لا تظهر خيارات تقترح تحليل ملفات أو قراءة مجلدات.

### الفعلي — المحاولة 1 / شات جديد
```text
نعم.

المصادر المرفقة الظاهرة لي:

1. `project_root` (قائمة ملفات ومجلدات المشروع)
2. `README.md` (ملف التوثيق الرئيسي للمشروع)
```
ثم ظهر:
```text
TREE . Analyzed
✅ تم الجمع التلقائي للمعلومات
```

### الفعلي — المحاولة 2 / شات جديد
```text
نعم.

المصادر المرفقة الظاهرة:

1. `project_root`
2. `README.md`
```
ثم ظهرت خيارات تحليل/قراءة مثل:
```text
اقرأ محتويات مجلد Root للتعرف على حالة المشروع الحالية
حلل كود أحد السكريبتات...
راجع سجل المشاكل...
اشرح بنية المشروع بالتفصيل
```
وظهر أيضًا:
```text
TREE . Analyzed
✅ تم الجمع التلقائي للمعلومات
```

### التصنيف
- BUG-ATT-001 مؤكد بدرجة أعلى: شات جديد لا يعني صفر سياق/مرفقات؛ `project_root` و `README.md` يدخلان تلقائيًا.
- BUG-AUTO-001 مرتبط: أمر `لا تحلل المشروع` لم يمنع `TREE . Analyzed` والجمع التلقائي.

### ملاحظة تقييمية
قد يكون `project_root` سياقًا نظاميًا افتراضيًا وليس attached-content يدويًا، لكن واجهة/نموذج الرد يصفه كمصدر مرفق. هذا يخلق لبسًا خطيرًا في الاختبارات؛ يجب التمييز بين:
- مرفقات المستخدم اليدوية.
- سياق المشروع التلقائي.
- سياق خارجي/قديم.

### اقتراح إصلاح فقط — بدون تنفيذ الآن
- إضافة تصنيف واضح للمصادر في prompt/واجهة الرد: `system_project_context` مقابل `user_attached_files` مقابل `stale_external_context`.
- إذا prompt يحتوي `لا تحلل المشروع`، يجب تعطيل auto-analysis/Tree gathering لهذه الرسالة.
- إذا prompt يسأل عن وجود مرفقات فقط، لا يتم إدخال README.md تلقائيًا كأنه مرفق.
- إضافة زر/أمر واضح: `No Context / Zero Context Mode` للاختبارات.
